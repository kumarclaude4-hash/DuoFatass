## Changes

Only `scripts/AndroidReleaseLogPrivacyPolicy.java` changed in PR #286.

1. **Generic returns and chained receivers.** The syntax index now records class type parameters and identifies app-owned method returns containing unresolved class- or method-level type variables (for example `T getValue()`, including type variables inside parameterized return declarations). When such a result is logged or used as an intermediate receiver, the analyzer fails closed rather than allowing an unknown generic value to become a safe-looking receiver.
2. **Reflection and dynamic loading.** Common Java reflection/class-loading paths are treated as opaque data boundaries: `Class.forName`, `ClassLoader.loadClass`, reflective method/field lookup and access, `Method.invoke`, constructor/class instantiation, and method-handle lookup/invocation. They are not treated as sanitizers or safe helper returns.
3. **Callback lambdas.** Lambda parameters are treated as opaque callback inputs inside the lambda body. The method-local taint environment is snapshotted and restored at the lambda boundary so inferred parameter names cannot taint unrelated outer locals. Newly tainted captured containers remain tainted. At the sink walker, callback parameter names are scoped to the active lambda path rather than added to a compilation-unit-wide Throwable set.
4. **Narrow diagnostics retained.** The existing `getClass().getSimpleName()` projection is allowed for the active callback parameter without allowing raw callback values. `what` and `extra` are exempt only in `VoiceMessagePlayer`, where the app's `MediaPlayer.OnErrorListener` receives integer error codes. No general identifier-name allow-list was added.

## Regression coverage

The AST self-test suite now includes:
- A generic `GenericBox<T>.getValue()` receiver chain reaching `Log.w`.
- A `Class.forName` → `getMethod` → `Method.invoke` flow whose result reaches `Log.w`.
- An opaque `Consumer<Object>` callback parameter interpolated into a log sink.
- A safe callback exception-class-only diagnostic that must remain accepted.

The regression work also exposed and fixed test-visible scope contamination before the final successful head: an intermediate implementation leaked callback parameter names into unrelated locals, then a follow-up narrowed the class-name diagnostic to the active lambda path and separated callback names from Throwable classification. Those intermediate heads failed the AST gate and were superseded; no failed head was merged.

## Residual risk / explicit non-claims

This is not a whole-program taint proof. Remain conservative about:
- External/library subclasses and dispatch not represented by indexed app source.
- Reflection, class loading, method handles, generated bytecode and proxy paths outside the recognized Java API forms.
- Method references and opaque third-party callback internals.
- Native behavior and provider/library code with no inspectable implementation.
- Arbitrary generic substitution, collection/container semantics and alias forms beyond modeled source patterns.
- Receiver and control-flow/data-flow forms the bounded syntax resolver does not model.

The automated scan proves only the current source snapshot under this guard's modeled rules. It does not prove that runtime code never logs private values, and does not replace inspection of release/minified APK logcat on supported physical devices. That device acceptance remains deferred by the owner until app feature completion. Do not test physical devices early.

No production secrets, provider settings, credentials, release deployment or production configuration were accessed or changed. `security-remediation/FINAL_SIGNOFF.md` remains **PENDING**.
